# Упрощенная система управления воркерами

## Принципы работы

### 1. In-Memory Only
- Все данные о воркерах хранятся только в памяти (WorkerRegistry)
- Никаких файловых реестров или межпроцессной синхронизации
- Бэкенд следит только за воркерами, которых сам запустил в текущей сессии

### 2. Простая логика жизненного цикла
- Воркер запущен → регистрируется в WorkerRegistry
- Воркер остановлен → удаляется из WorkerRegistry
- Проблемы остановившегося воркера → это проблема конкретного воркера
- Остановился → следующий в очереди запускается

### 3. VIP Timeout из .env
```env
# VIP Timeout Settings (in minutes)
VIP_0_TIMEOUT=2    # Обычные пользователи: 2 минуты
VIP_1_TIMEOUT=10   # VIP 1: 10 минут
VIP_2_TIMEOUT=20   # VIP 2: 20 минут
VIP_3_TIMEOUT=30   # VIP 3+: 30 минут
```

## Компоненты системы

### WorkerRegistry (worker_registry.py)
- In-memory хранилище активных воркеров
- Методы: add_worker(), remove_worker(), is_worker_running(), get_worker_info()
- Автоматическая очистка мертвых процессов

### QueueManager (queue_manager.py)
- Управление очередью запуска воркеров
- Проверка неактивных воркеров с VIP timeout
- Автоматический запуск следующего в очереди

### WorkerAPI (api/workers.py)
- Упрощенные endpoints: /start, /stop, /status, /heartbeat
- Работает только с WorkerRegistry (in-memory)
- Никаких файловых операций

### ServiceStatus (api/queue.py)
- Endpoint /service-status для ServiceHeader
- Получает данные из QueueManager.get_queue_info()
- Показывает актуальное состояние воркеров

## Поток данных

```
1. Пользователь → /api/workers/start
2. QueueManager → добавляет в очередь
3. QueueManager → запускает воркер (если есть место)
4. TelegramWorker → регистрируется в WorkerRegistry
5. ServiceHeader → получает данные из /api/queue/service-status
6. QueueManager → проверяет неактивных воркеров (VIP timeout)
```

## Ограничения

### ⚠️ Перезапуск сервера
- При перезапуске API сервера теряется информация о воркерах
- Воркеры продолжают работать, но не отображаются в интерфейсе
- Решение: перезапуск воркеров или ручная синхронизация

### ⚠️ Мониторинг
- Нет персистентной истории воркеров
- Статистика доступна только во время работы сервера
