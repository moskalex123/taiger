# Устранение неполадок

Этот документ содержит решения типичных проблем при работе с проектом Taiger.

## Проблемы с запуском

### Порт 8000 занят

```bash
# Проверить, что занимает порт
lsof -t -i:8000

# Остановить процесс
kill -9 $(lsof -t -i:8000) 2>/dev/null || echo "No processes found on port 8000"
```

### Ошибки подключения к базе данных

1. Проверьте переменные окружения в `.env`:
   ```bash
   cat .env | grep DB_
   ```

2. Проверьте доступность базы данных:
   ```bash
   psql -h 94.141.161.21 -p 5433 -U taiger -d taigerdb
   ```

3. Проверьте логи приложения на наличие ошибок подключения

### Ошибки подключения к Redis

1. Проверьте, что Redis запущен:
   ```bash
   redis-cli -h localhost ping
   ```

2. Проверьте настройки в `.env`:
   ```env
   REDIS_HOST=localhost
   REDIS_PORT=6379
   ```

## Проблемы с воркерами

### Воркер не запускается

1. Проверьте логи воркера:
   ```bash
   tail -f logs/worker_*.log
   ```

2. Проверьте наличие сессии Telegram:
   - Убедитесь, что сессия загружена из S3
   - Проверьте права доступа к сессии

3. Проверьте статус воркера в API:
   ```bash
   curl http://localhost:8000/api/workers/status
   ```

### Воркер зависает

1. Остановите зависший процесс:
   ```bash
   pkill -f "tg_worker.py.*--user_id <USER_ID>"
   ```

2. Очистите реестр воркеров (перезапустите API сервер)

3. Проверьте логи на наличие ошибок

## Проблемы с авторизацией

### Ошибка "Invalid authentication data"

1. Проверьте `TELEGRAM_BOT_TOKEN` в `.env`
2. Убедитесь, что время на сервере синхронизировано
3. Проверьте, что используется правильный домен для TMA

### 2FA не работает

1. Проверьте логи на наличие ошибок SessionPasswordNeeded
2. Убедитесь, что фронтенд правильно обрабатывает 2FA
3. Проверьте, что пароль передаётся корректно

## Проблемы с фронтендом

### Ошибка 403 Forbidden после сборки

**Проблема:** После сборки фронтенда nginx возвращает ошибку 403 Forbidden.

**Причина:** Файлы в `frontend/dist/` создаются с правами root, а nginx работает от пользователя www-data.

**Решение:**

1. Используйте скрипт сборки с автоматическим исправлением прав:
   ```bash
   cd /opt/taiger/frontend
   sudo ./build.sh
   ```

2. Или вручную исправьте права после сборки:
   ```bash
   cd /opt/taiger/frontend
   npm run build
   sudo chown -R www-data:www-data dist/
   ```

3. Перезагрузите nginx:
   ```bash
   sudo nginx -t && sudo systemctl reload nginx
   ```

**Примечание:** Скрипт `build.sh` автоматически исправляет права доступа после сборки.

### Изменения не применяются

1. Пересоберите фронтенд:
   ```bash
   cd frontend
   npm run build
   sudo chown -R www-data:www-data dist/
   ```

2. Очистите кэш браузера
3. Проверьте версию в `frontend/.env`:
   ```env
   VITE_APP_VERSION=v1.0.0
   ```

### WebSocket не подключается

1. Проверьте, что WebSocket endpoint доступен:
   ```bash
   curl http://localhost:8000/api/ws/2
   ```

2. Проверьте настройки CORS в `main.py`
3. Проверьте логи на наличие ошибок WebSocket

## Проблемы с обработкой постов

### Посты не обрабатываются

1. Проверьте, что воркер запущен и активен
2. Проверьте правила обработки в базе данных
3. Проверьте баланс пользователя
4. Проверьте логи воркера на наличие ошибок

### ИИ не обрабатывает текст

1. Проверьте API ключи в `.env`:
   - `OPENROUTER_API_KEY`
   - `HYPERBOLIC_API_KEY`

2. Проверьте баланс на провайдерах ИИ
3. Проверьте логи обработки ИИ

## Проблемы с балансом

### Баланс не списывается

1. Проверьте логи списания баланса
2. Проверьте настройки цен моделей в базе данных
3. Проверьте, что баланс достаточен для операции

### Баланс не обновляется

1. Обновите страницу в браузере
2. Проверьте API endpoint `/api/users/me`
3. Проверьте логи на наличие ошибок

## Общие проблемы

### Логи не отображаются

1. Проверьте настройки логирования в `main.py`
2. Проверьте права доступа к файлам логов
3. Проверьте WebSocket соединение

### Производительность низкая

1. Проверьте нагрузку на базу данных
2. Проверьте использование памяти
3. Проверьте количество активных воркеров
4. Рассмотрите увеличение `MAX_CONCURRENT_WORKERS`

## Получение помощи

Если проблема не решена:

1. Соберите логи:
   ```bash
   tail -n 1000 logs/*.log > debug_logs.txt
   ```

2. Проверьте статус всех сервисов:
   ```bash
   curl http://localhost:8000/health
   ```

3. Обратитесь к разработчикам с описанием проблемы и логами
